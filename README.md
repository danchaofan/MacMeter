# MacMeter

原生 macOS 菜单栏 CPU、内存、网速和电池监控工具。macOS 13 Ventura 或更新版本，无第三方依赖，不发起网络请求，不需要管理员权限。

当前应用显示名称为「资源看板」，源码版本为 1.2.1。

## 运行

下载发布包后解压，双击 `资源看板.app`；从源码构建的应用位于 `dist/资源看板.app`。顶部菜单栏出现波形图标和 CPU / MEM 百分比。左键展开四卡看板，右键显示快捷菜单。应用不在 Dock 中常驻。

面板关闭后再次点击菜单栏入口，会从首页打开；实时采样与历史数据继续保留。

如需开机启动，建议先把 `.app` 移到「应用程序」文件夹，然后在设置中开启「登录时启动」。系统要求批准时，点击界面中的系统设置入口完成。

## 功能

- CPU 全机使用率、内存已用 / 总量、系统内存压力。
- 网速：实时下载 / 上传速率，点击卡片查看活动接口和统计口径。
- 电池：电量百分比、供电来源、充电状态、系统提供的充满 / 剩余时间、低电量模式状态。二级页展示健康状态、最大容量、循环次数、满充容量和设计容量。无内置电池的 Mac 显示明确状态。
- 最近 5 分钟趋势，按实际采样时间绘图；睡眠和采样中断不会连成连续数据。
- 按 CPU / 内存排列应用，合并应用包内的辅助进程和可识别的子进程。
- 应用详情、正常退出、确认后强制结束；自身和 Finder 等桌面组件受保护。
- 内存明细：联动内存、压缩内存、可回收缓存、交换空间。
- 持续异常时发送系统通知：CPU 超过 85% 持续 60 秒；内存压力严重持续 30 秒。
- 同一次连续异常只通知一次；恢复后再次异常仍受 10 分钟间隔限制。
- 菜单栏可选 CPU + 内存、仅 CPU、仅内存、仅网速、仅电池或仅图标；1 / 2 / 5 秒刷新，系统登录启动，设置保存在本机。
- 首次开启提醒时申请通知权限，默认不开启提醒；点击通知可打开看板。

## 指标说明

CPU 总量和应用列表都按整台机器的 0–100% 口径计算。例如，8 核机器中一个逻辑核持续满载约占全机 12.5%。这与活动监视器单进程可超过 100% 的口径不同。首个采样周期显示 `—`，避免把进程累计运行时间误算为当前占用。

已用内存使用内核 VM 页统计估算：内部页 + 联动页 + 压缩页，减去可清除页；文件缓存不计入已用。内存压力来自系统，不按内存百分比臆测。应用内存使用物理内存足迹，辅助进程加总是估算，无法与系统内存逐项相加对齐。

排行展示当前用户的可读取、带界面的应用。部分受系统限制的进程、短命进程以及无法归属的辅助进程可能缺失；可打开活动监视器查看全部系统进程。不申请完整磁盘访问、辅助功能或录屏权限。

强制结束可能丢失未保存的更改。正常退出后应用可能显示保存提示，看板会说明应用是否仍在运行。

网速以活动物理 `en*` 接口的 64 位字节计数差值计算，检查物理连接状态，排除回环、VPN 隧道、虚拟桥接与无线直连接口，避免重复统计；同时使用多个物理接口时合并其流量。包含局域网和 VPN 加密后经过物理网卡的流量，不是主动测速，不会额外下载测速文件。采用十进制 B/s、KB/s、MB/s，区别于网络带宽的 Mbps。新接口、计数器重置、断网和睡眠恢复不会产生累计流量尖峰；首次采样显示 `—`。

电池运行状态和健康状态来自公开 IOKit Power Sources API；额外从 AppleSmartBattery IORegistry 只读获取循环次数与硬件容量。优先采用系统直接报告的最大容量百分比，否则使用满充容量 / 设计容量估算并明确标注，可能与系统设置略有差异。不会把当前剩余电量当作最大容量，也不会把部分机型归一化的 `MaxCapacity = 100` 误当成 mAh。缺失字段显示“系统未提供”，不根据循环次数或当前电量推断维修状态。不修改电池或充电策略。

## 构建

安装 Xcode Command Line Tools 后，在项目目录运行：

```bash
bash scripts/build.sh
bash scripts/test.sh
```

默认生成当前机器架构的应用。构建其他架构：

```bash
RB_ARCH=arm64 RB_OUTPUT_DIR=dist-arm64 bash scripts/build.sh
RB_ARCH=x86_64 RB_OUTPUT_DIR=dist-intel bash scripts/build.sh
```

直接构建双架构通用版：`bash scripts/build-universal.sh`。

本地包使用 ad-hoc 签名，未做 Apple 开发者签名和公证，适合本机使用；分发给其他 Mac 前应使用 Developer ID 签名并公证。

## 隐私与本地数据

应用在本机读取资源占用、当前用户可读取的应用进程信息、物理网卡字节计数和电池指标，不上传数据、不访问网络服务，也不采集设备序列号。实时数据和短期趋势保存在内存；显示偏好、刷新频率和提醒开关保存在系统 UserDefaults 中。

只有显式运行 `--smoke-test` 时，才会向指定目录写入诊断报告与界面截图。这些文件可能包含正在运行的应用名称、进程 PID、安装路径、资源占用及电池信息，发布前应单独检查。仓库仅包含源码、文档和构建脚本，不包含这些实机诊断、截图、安装包或本机设置；测试数据使用合成样例。

## 验证

`scripts/test.sh` 检查 CPU 计量、计数器回绕、应用与辅助进程归属、PID 重用、提醒阈值 / 冷却、受保护进程、网络 64 位计数与采样间隔、接口变化 / 断网 / 唤醒、速率单位、电池各状态、健康字段缺失 / 维修提示 / 最大容量与电量区分 / mAh 单位，以及真实内核 / 接口 / 电源采样。

`scripts/test-integration.sh` 会启动两个专用测试应用，验证正常退出、拒绝退出、强制结束和过期身份保护；只会结束该测试自己启动的应用。此测试需要在正常的 macOS 图形会话中运行。

界面烟雾测试（生成真实数据报告和界面 PNG，至少两个有效采样后自动退出，最长等待约 25 秒）：

```bash
dist/资源看板.app/Contents/MacOS/ResourceBoard --smoke-test /absolute/path/to/test-output
```

烟雾测试不会终止任何其他应用，不会自动开启通知或登录启动。测试文件包含当时的真实运行信息，仅保存在指定的本机目录，默认应保留在本机。

烟雾测试也会验证「进入电池二级页 → 关闭面板 → 从菜单栏入口重新打开」：检查视图会话已重建、监控数据未重置，并生成 `reopened-board.png` 供检查首页显示。
